# Working notes for an AI assistant in this repository

These notes, like the Lessons Learned, were written with and for Claude Code and read best there. They are meant to help any AI assistant that works on this repository, but they were not tested with another one, and the setup steps assume a Claude Code cloud session on Ubuntu.

## What this is

Thirty-one teaching programs for the HP Prime calculator in PPL (five carry MicroPython), each a plain `.txt` file in `programs/`, and the HP Prime Data Loader web page (`data-loader/`) that feeds one of them, DataLoad; with a four-tool gate, a PC harness, one verify script per program version, a change note and device checklist per version, and the Lessons Learned document on how the Prime actually behaves. Read `START_HERE.md`, then `docs/lessons-learned_v7zx.md` (or the newest letter) before writing any PPL. The author is Roger Metcalf; the HP programs are his, and every change goes through a pull request he merges.

## How to work here cheaply

The author's cloud credit is spent on tokens, not on processor time. So:

- **Before any task, choose the way that does the job properly at the least cost**, and say the expected cost before starting anything likely to exceed a few dollars. Compute is cheap and tokens are dear: a script that runs for an hour and prints ten lines beats ten minutes of reading. If two methods give the same result, take the cheaper one; if the cheaper one gives a weaker result, say what it loses and let the author choose.
- **Prefer a script that runs long and prints little.** Run checks and sweeps in the background, filter their output to the lines that decide something, and read a summary, never a whole log.
- **Do not read whole programs into the conversation.** A program is 1,000 to 6,000 lines. Grep for the routine you need and read that routine. Check a formula by calling its routine through the harness (`h.execute('es_WilsonCI(5,20)')`, or `h.globals_.update({...})` then `h.execute('csCompute()')`), not by reading or driving its pages.
- **Do not spawn parallel agents** for reading; they multiply the cost. One session, one thread.
- **Never stop a background task in a way that echoes its script back** (the TaskStop echo was the most expensive moment of a whole day). Prefer `pkill -x python3` over `pkill -f <pattern>`, which also kills the shell that contains the pattern.
- **Say the usage** in tokens at each milestone when asked; the author watches a dollar meter.

## Setting up a fresh session (about five minutes)

```
pip install scipy statsmodels sympy
apt-get update && apt-get install -y xcas          # gives icas, the Giac the harness uses for CAS calls
git clone --depth 1 https://github.com/JordiRigau/hp-prime-kit /tmp/kit/hp-prime-kit-HEAD
export HPKIT=/tmp/kit/hp-prime-kit-HEAD              # the harness finds the kit here
```

The Virtual Calculator itself can be stood up in the session, under Wine, in about ten minutes: `tools/vc_cloud_v1/README.md` has the recipe, the patch and the driver (15 Nov 2026). HP's installer comes from the author's `D:\HP-Prime` and is never committed, nor is the patched program.

The gate (`tools/ppl_gate_v1e.py`) finds the kit only as a zip, `Community_Library/github/JordiRigau__hp-prime-kit.zip`, beside `tools/` or one folder up. Do not put it inside this repository: copy `tools/` to a scratch folder, zip the kit beside that copy, and run the gate from there, pointing it at `programs/`.

## The checks

- **Gate, before any paste**: `python3 ppl_gate_v1e.py NEW.txt [ORIGINAL.txt]`; every program in `programs/` passes. "PARSE FAIL" on the √ character, `#RRGGBB:24h` colours or forward declarations is the kit's limit, not an error; the kit linter's "0 errors" is the line that matters.
- **Text overlap** (since 28 Oct 2026): `python3 tools/text_overlap_v1.py --run verify/verify_<Name>.py` or `--walk programs/<Name>.txt`; no firm overlaps, straddles or overruns on any page.
- **Fleet names**: `python3 tools/fleet_names_v2.py programs/*.txt` (all programs share one pool of routine names on the calculator).
- **Screen text** (since 17 Nov 2026): `python3 tools/screen_text_v1.py programs/*.txt`; no place against the rules for a statistic's letter (Conventions, below). It reads every quoted string of the code; with `--walk DIR` it also reads every text the generic walks drew (`text_overlap_v1.py --walk FILE --json DIR/<stem>.json`; 31 walks are 381 MB, so keep the lists of their distinct texts that `verify/round17/drawn_texts_r17.py` writes, never the walks).
- **Verify scripts**: the newest ones run from `verify/` as they are and read older versions from git: round 6's, one for each of the 11 programs it changed (`verify_<Name>_<version>.py`, 2 Nov 2026, night; BurrLab's beta 1k, never committed, sits beside them as `verify/BurrLab_beta1k.txt`), round 5's, one for each program, and before them `verify_StudRange_beta15f.py` and `verify_TrendTest_beta3g.py`. A round-5 script checks what round 5 changed, the commas, against the version before (`tools/comma_check_v1.py`); the program's earlier script still holds its arithmetic and dialog checks. The 19 October scripts hard-code the author's folders (`/home/claude/work/...`) and need files that are not in the repository; `verify/README.md` and `docs/dev/independent-review-2026-10-22.md` say what they need and what happened when they were rerun. Since round 11 each round also has a folder, `verify/roundNN/`, with its build scripts (a program is built from the version before by exact replacements), its records and a README; round 17's (17 Nov 2026) is the newest. A round that changes only words has one script for all its programs (`verify_round17_screen_text_v1.py`: only text inside quotation marks changed, every changed text is seen on a screen of the new version, and it fits).
- **Monkey test** (since 1 Nov 2026; the book's vetting point 6): `python3 tools/monkey_v1b.py programs/<Name>.txt "CALL()" --runs 1000 --lists [--writes D,C]` (v1b applies `tools/prime_facts_v1.py`, the device facts the harness does not model yet). A long job goes in chunks written as they end (`tools/monkey_chunks_v1.py`; a program paced by the clock, such as GaltonBoard, gets 120 s a run). Since 2 Nov 2026 every verify script's D part runs `tools/label_fit_v1.py` beside `text_overlap_v1` (a number cut short by its width argument), and `tools/monkey_labels_v1.py` checks every program's labels under random use (`docs/dev/label-check-2026-11-02.md`). Every run must end OK (STATE only for what `--writes` names); a broken run's seed replays it (`--replay SEED`). Number fields are `{name,[0]}`, which refuses a typed list on the calculator. **A new page that random keys seldom reach gets directed runs too** (15 Nov 2026): `tools/monkey_reach_v1.py` counts how many of the monkey's sessions showed the page (Dunnett's table: 3 of 300; a tolerance interval: 0), and `tools/monkey_directed_v1.py PROG CALL BASE K0 K1 OUT.jsonl --lead "[...]" --reach "REGEX"` starts each session on the page by a scripted lead and then hands over to the monkey; a run that never showed the page is MISSED (`verify/round16/directed_r16.py` is the model).
- **Python**: `cd python && python3 test_hpstats.py` checks `hpstats.py`, the fleet's arithmetic, against SciPy, statsmodels and brute force.
- **Harness smoke test**: load each program in `tools/ppl_run_v3e.py` with `idle_key=4` and call its main routine; zero warnings and no `PPLError` is the pass.

## Conventions

- A changed program gets the next letter (`beta 15d` → `beta 15e`), replaces the old file in `programs/` (git keeps the old one), updates its header and its "What changed" block, and gets `docs/changes/<name>_CHANGES.md` (why, what changed with line numbers, verification, gate, device checklist, unresolved), a `verify/verify_<name>.py` with its output beside it, a line in `verify/README.md`, and a bullet in the README's test-status note plus its row in the program list.
- **After any change in `programs/`, rebuild the starter pack** with the next number, in two passes (`docs/changes/StarterPack_v5_NOTES.md`): build without `--checked` (`python3 tools/make_starter_pack_v4.py v7 --kit $HPKIT`); load it on the Virtual Calculator (close it, copy the files in, start it), Check each changed program and run nothing, close it, and copy those files back into the checked-files folder (a checked file keeps the file-level values of its last run, so a run would ship that run's numbers: `docs/changes/StarterPack_v6_NOTES.md`); then build again with `--checked FOLDER`, which stops unless every program has a checked file holding its exact source. Move the older zip out of `starter-pack/`, and rebuild the Prime Loader from the new pack (the newest `prime-loader/build_loader_v*.py`, then its test).
- **GitHub Pages** (1 Nov 2026): the repository is published at https://metcalfdds.github.io/hp-prime-statistics/ (Settings → Pages, `main`, root). `.nojekyll` keeps Jekyll off, because PPL list syntax such as `{{x,y}}` in the Markdown breaks its Liquid templates. The front page, `index.html`, links to `prime-loader/` and, since 17 Nov 2026, to `data-loader/`: each folder's `index.html` is written by its page's build and sends the browser on to the current page, so neither the front page nor the address the book prints changes with a version. A pack that lags `programs/` gives students old versions.
- **The data loader** (`data-loader/`): edit `page_template_v5.html` or `dl_core_v2.js` under a new version number, rebuild the page with its `build_page_vN.py`, and run `node tests/test_core_v2.js` (the encoder against hp-prime-kit's, the Rossi file byte for byte, and the pastes a student makes) and `node tests/page_check_v5.js` (the page in Chromium; Playwright). A change to what the page writes must be loaded with DataLoad on the Virtual Calculator before it is called tested. Its last step links to the Prime Loader with `?data=1`, and names the Loader's step and button: when the Loader's layout changes, the Data Loader's two lines change with it.
- **The Prime Loader** (`prime-loader/`, v2h since 18 Nov 2026). The page asks which calculator and has one button. **The Virtual Calculator takes all the programs, with nothing to choose; a real HP Prime takes one group of chapters at a time** (Roger, 18 Nov 2026: "for the Virtual Calculator: load all programs at once; then for a physical G1 or G2 choose 1) Ch 1-3, 2) Ch 4-6, 3) Ch 7--9. 4) Ch 10-12, 5) Ch 13-15, 6) Advanced 1, 7) Advanced 2, 8) Advanced 3"), because neither of his calculators held all 30 programs: the G1 was full after 15 (about 2.1 million characters) and the G2 stopped at the 14th. The build makes the groups (`build_loader_v2j.py`, `CHAPTER_GROUPS` and `ALONE`; no group over 1,300,000 characters, or the build stops), so a new program or a changed chapter plan changes them there and nowhere else. **Advanced 1 is EpiStats alone** (Roger, 18 Nov 2026: "I wounder if we maybe should handle EpiStats separately from the others?"): sent to his G1 with two programs behind it, it would not run and the calculator reset; sent alone, it ran. **By the cable, the book's programs that are not in the chosen group are taken off the calculator before the group goes on** (Roger: "Yes, take them off"); a name that is not the book's is never sent a delete. On the Virtual Calculator nothing is deleted: a replaced file goes to the backup (`loader_core_v3.js`). Ticked programs and data, under "More choices", are added on either calculator. Its test (`tests/test_loader_v2j.js`, about twelve minutes) compares every file written with the pack byte for byte against a mock of `Documents\HP Prime`, and what the cable puts on a pretend calculator with the pack's source character for character. **The Connectivity Kit's steps stay on the page, whole, whatever the cable comes to do** (Roger, 17 Nov 2026: "maybe we shoould keep the instructions for the COnnectivity Kit as a backup"): the Kit is way 2) for programs and still the only tried way for CentralLimit and for data files. **Where both ways show (Chrome or Edge, a real HP Prime), the step is called "Two ways to load *Statisticles* onto a physical Prime G1 or G2 calculator"** (*Statisticles*, in italics, is the book's name for its programs), **and its two ways are "1) The *Statisticles* way" (the cable) and "2) The official HP way" (the Connectivity Kit)** (Roger's names), never "the first way", "the second way" or "the other way". Under the title stands his sentence as the book has it ("We believe our method should work, and we have tested it, and are continually testing it. ..."), with the repository's Issues address; "and we have tested it" went in on 18 Nov 2026, when a chapter had gone to a G2 and to a G1 and a program of it had run. **The page's words for the cable say "verifying the download"** (Roger: "instead of saying 'asking for program back' say 'verifying download'"). **The programs are called *Statisticles*, in italics, where a sentence allows** (Roger, 18 Nov 2026: "we should refer to these as Statisticles when possible"): "the *Statisticles* programs", not "the book's programs". **The cable's first step asks for a restart, if the student can** (Roger: "if possible, they should do a paperclip reset first before anything else"), **and the first step when the programs are on is to unplug the cable**, because his G1 was "very slow" on it and "went back to normal speed" unplugged. In Firefox or Safari, which cannot reach a USB device, one sentence above the Kit's steps names Chrome and Edge. The book's section for a real calculator takes the same title, names and sentence (`cable_sections_v1g.md`, held with the book's source).
- **A real HP Prime on its cable** (`prime-loader/usb/`, 17 Nov 2026; Roger: "do we need the Kit?"). `prime_usb_v3d.js` is written from four public descriptions of the cable (hp-prime-kit, hp-prime-web, PrimeDev, hp-prime-emulator; each fact is marked with its source) and from thirteen logs of the author's own G2 and G1 (`usb/logs/`: five from test pages on 17 Nov 2026 and eight from the Loader on 18 Nov; `usb/README.md` has the tables). **The route both calculators took**: "who are you"; `FD 01 00 00 00 01 03` in the old framing; the newer framing (`FF EC`); each program NOT compressed (`F7 01`), then asked for back. A program the browser compresses is not kept, and the old framing ends at 255 reports. It is tested against hp-prime-kit's own code byte for byte and against a pretend calculator, `usb/tests/mock_prime_v3c.js`, which by default does what those two calculators did. **A pass against the mock is not a calculator**: a thing about the cable is called tested only when a page has run it on a real one and its log is in `usb/logs/`, and a new thing the cable does (v2h's rest after each program, for one) is written as not yet seen on a calculator until it has been. A fact a log teaches goes into the mock the same day, as a device fact goes into `tools/prime_facts_v1.py`. **Every wait has an end** (the first page stood still on a real calculator, 17 Nov: "the program seems stuck"): a wait is counted once from when it starts, whatever arrives meanwhile; the browser's `disconnect` ends every wait at once; and a test in which the calculator goes off the cable in the middle of a write is part of any change to this code. **What the calculators taught, each at the cost of a run** (17 Nov, the second test): send 77 reports and wait for the acknowledgement, because the calculator acknowledges every 77th; believe a word of the calculator's for the room it carries, not for its kind, because its clock says "send again" for a report that is still on its way (one report again, then listen, never a run of them); give an answer time in proportion to the program, because the calculator compresses it first (a G1: 3.1 s for 289,813 characters), and far more than that, because a G2 that was filling up took 22 s (30 s and 0.1 ms a character now); and never leave an answer of the calculator's unacknowledged or thrown away, because a G1 left so answered nothing more, and a G2 left so (18 Nov, when the page gave up on EpiStats) kept offering the old answer all through the next load, until it was switched off and on. **What 18 Nov taught:** a full calculator says nothing: a G1 acknowledged every report of a program and kept only its name (the read-back is empty: `full`); a G2 took one report and then none, still on its cable (`stuck`, said as "stopped responding", never as "went off the cable"). **And a verified program does not always RUN:** on the G2 two of four programs opened the editor at Run until they were Checked, and on the G1 EpiStats, with two programs sent behind it, reset the calculator at Run; the last program of a send has always run, and EpiStats sent alone ran. Why is not known (`usb/README.md`, "What ran afterwards"). So `load` rests the calculator after each program, once its download is verified (`lullFor`: 2 s and 0.5 s more for each 100,000 characters on a G2, 2 s more on a G1; chosen, not measured), and "verified" is never written as "runs": only a person at the calculator can say that a program ran. Every report in and out passes the trace, so that a log shows what the calculator did and not only what the code made of it. The calculator's serial number is never read, logged or shown; a log line shows twelve bytes of a message at most. A number the READMEs give for the cable (reports, characters) is counted in `test_usb_core_v3d.js` (A18) or `test_loader_v2j.js`.
- Lessons Learned is versioned by letter too (`v7y` → `v7z`), with a "What changed" block at the top; the links in `README.md`, `docs/README.md` and `START_HERE.md` are updated with it.
- Executable code stays ASCII (`ppl_check_v5.py`'s E5); π is `3.14159265359`. Strings may carry any glyph GfxProbe has shown renders. Every routine and local name carries the program's prefix (`st_`, `cs`, `tr`, `dm` …) so the fleet shares one name pool safely.
- **Commas in big numbers** (2 Nov 2026; Roger: "always put comma delimiters in big numbers"). Every number of 1,000 or more that reaches the screen goes through the program's comma routine (`<prefix>Cm`, word for word `tools/comma_helper_reference_v1.txt`) where it becomes text, so it is measured with its commas before it is drawn. Never in text the CAS or `EXPR` reads, never in a year, never in a name with digits in it ("x1000"). A changed program keeps to this by hand or through `tools/commas_v1.py`'s rules, and its verify script runs `tools/comma_check_v1.py`. Prose follows the same rule: 1,000 and up get commas (APA).
- **Sensible ranges for what a student types** (2 Nov 2026, night; round 6, `docs/dev/caps-2026-11-02.md`). A typed value outside its range is refused with a sentence that says the range, and nothing changes; never clamp it without a word. Alpha is from 0.001 to 0.2 in every program (help line "From 0.001 to 0.2; 0.05 is usual"), and a drag stops at the same ends. A cap goes where the program stops being right or readable (a cell that shows 9,999,999 whole; StudRange's df at 100,000); values in the data's own units stay open. Find the fields with `tools/caps_probe_v1.py`. A menu item (`CHOOSE`) is at most 30 characters: the box sizes itself to about 214 px and cuts the rest. A menu's title shows 31 characters and no more (AnovaLab on the Virtual Calculator, 15 Nov 2026): count the longest title a program can build. A menu shows eight items; a ninth is cut off at the bottom of the screen (TTestLabG on the Virtual Calculator, 14 Nov 2026), so a menu whose every item must be in sight has at most eight. A longer menu scrolls and is no fault: 37 of the fleet's 160 menus list more than eight items, and Help comes after the eighth in 16 of them (`verify/round14/menu_count_v1.py`, run again on 15 Nov 2026); changing those is the author's choice.
- **A statistic's letter on the screen** (17 Nov 2026; Roger: "The p-value and t-test, t-distribution etc should be hyphenated and italicized"; "make sure expressions like n-1 are in parentheses"). A screen has no italics, so a program's text keeps the rest of the book's rule. A hyphen joins the letter to its noun: F-test, z-test, t-table, t-curve, t-interval, z-values, and p-value with a small p, at the start of a title too; "t critical value" and "t crit" take none. An expression like n - 1 stands in parentheses of its own: df = (n - 1), (k - 1) df, df = (N₁ + N₂ - 2); a sentence is turned so that no parenthesis stands inside another ("Breslow-Day, (k-1) df:"). The Prime's own names stay as the Prime spells them (Linear t test, T-Test: 1 μ), and comments keep their wording. `tools/screen_text_v1.py` is the check. After any change of words, dump the help pages again and measure the line: two more characters filled FitCheck's help 4 of 12 and made a thirteenth page of one word, a line that flows must not break inside an expression, and at font 1 a hyphen is 6 px where a space is 3 (`verify/verify_round17_screen_text_v1.py`, T4 and T6; `verify/round11/glyph_widths_vc.json`).
- **What a program returns must fit its box** (15 Nov 2026). Run from the Program Catalog, the calculator shows the returned line in a box of five lines of about 26 characters and drops the rest (CICatcher on the Virtual Calculator). Keep the line to about 100 characters, and lay the longest one a program can give out in the verify script (`box_lines` in `verify/verify_CICatcher_beta2l.py`).
- **The book names menu items by number** (15 Nov 2026). A new item goes after the old ones where it can; where it cannot, the change note lists every item that moved, for the book's next draft.
- **A number in a comment is a claim** (15 Nov 2026): count it in the verify script and say where it was counted ("the PC harness takes 1 to 5"). A table a program needs (quadrature nodes, a counted distribution, the header's file map) is written by its build script, never typed.
- Compute upper tails as lower tails or as finite sums of positive terms; never `1 - CDF` where the p may be small. A tail summed over quadrature nodes is summed as it stands, Σ w f (1 − G) / Σ w f (AnovaLab's Dunnett engine).
- Take a standard deviation from the deviations x − x̄ in a second pass, never from Σx² − n x̄², which loses its digits when the mean is large next to s (the Prime keeps 12); a simulated sample adds up the z behind each value (Lessons Learned v7zi §11).
- A number a student can type is refused with a sentence before it is used when the program cannot draw it: 50 digits or more, a scale too small next to its location for 12 digits, and anything a family's formulas cannot hold (Lessons Learned v7zi; SampDist, CICatcher, Norm3, NormExplorer, StatDist).
- Nothing is reported as device-tested unless it ran on the Virtual Calculator, a G1 or a G2; the harness is a PC model. It counts in 16 digits (the Prime keeps 12), prints any number of decimals (`STRING(x, 2, d)` refuses d ≥ 13 on the Prime) and reads `!=` as "not equal" (on the Prime it is a factorial and a test: write `<>`). A device fact the harness lacks goes into `tools/prime_facts_v1.py` the same day; the verify scripts and the monkey test apply it.
- **Key presses on the Virtual Calculator** (15 Nov 2026). A page that waits by polling `GETKEY` loses about one key press in eight there; `WAIT(-1)` and Home lose none (`diagnostics/KeyProbe_beta1.txt`, `verify/round16/keyprobe_r16.txt`). Whether a G1 or a G2 loses presses is not known. When driving the Virtual Calculator, send a key again only after seeing that the screen did not change (`tools/vc_cloud_v1/vcdrive.py` does). Do not change the fleet's wait loop on this count alone: it waits for the author's count on a calculator.
- **Credits say what was done** (15 Nov 2026; Roger: "IS there an issue with 'reworking' the TI and Triola and Lloyd programs?"). Where a program does what another program does, its help page and its header say so in plain verbs: "Does on the Prime what X does", "written new", "none of its code" (and "without its bugs" where the header lists them). Write "reworks", "ports" or "replaces" only where code was carried over, and then say which. Six programs follow TI-83/84 programs (RankLab, AnovaLab, FitCheck, ResampLab, ExhibitLab, SurvLab); those were read to see what each one computes, and ours were written new in PPL (`docs/changes/FitCheck_beta1h_CHANGES.md`). A feature added because another program has it is written from its formula, and its change note says what was read.
- **A page a student uses is tested with a student's slips** (17 Nov 2026; Roger: "they must be bullet proof and as simple as possible"). The two loader pages passed every test they had, and each test did what a careful student does. Tried with the slips (a paste into a box that was not empty, NA in a column of words, `$45,000`, a file of the right name and the wrong content, a data file loaded with no chapter picked, the page opened on a phone), they went wrong without a word in the ways the two tables of `data-loader/README.md` and `prime-loader/README.md` list ("The review of 17 November 2026"). A new control or a new step on either page gets a test in which it is used wrongly, and whatever a page changes in what the student gave it, it says in a sentence on the page.
- **General and advanced versions** (31 Oct 2026). A program's general version (TTestLabG for TTestLab) is built from the advanced one by a script of exact replacements (`tools/make_tlg1_v4.py`, whose blocks are in `tools/tlg1_v4_blocks.txt`): a new name and tag, the companion guide's conventions, general examples. Change the advanced program first, then rebuild the general one with the script's next version, and derive its verify script from the advanced one's the same way, reading every failure before changing an expectation.
- **A verify script must drive every cancel and refusal path** (Esc at each menu, Cancel on each form, each refused read), not only the arithmetic: TTestLab's 59 arithmetic checks passed while ten dialog faults waited for the independent review (31 Oct 2026). A new program gets that review before it is called finished.
