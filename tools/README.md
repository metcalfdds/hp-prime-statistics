# Tools

Every program in this repository passes these checks before it is pasted onto a calculator. They are plain Python 3, and only `ppl_run_v3e.py` needs more (see below).

| File | What it does |
| --- | --- |
| `ppl_gate_v1d.py` | **The gate.** `python3 ppl_gate_v1d.py NEW.txt [ORIGINAL.txt]` runs the four checks below and the fleet name check, and prints PASS or the lines to look at. It finds the other tools and `HP_Prime_Builtin_Names.txt` in its own folder (or one folder up), so keep them together. It uses hp-prime-kit's linter and interpreter if it can find them (JordiRigau/hp-prime-kit, as `Community_Library/github/JordiRigau__hp-prime-kit.zip` beside it or one folder up); without them those two steps are skipped. v1c (19 October 2026) runs the kit's linter on a copy with the `#PYTHON … #END` blocks blanked, so a program carrying MicroPython no longer shows a false "unbalanced blocks" error, and uses `lint_ppl.py` version 2. v1b (17 October 2026) made `ppl_check_v4.py`'s E12 a hard error. v1d (1 November 2026) runs `ppl_check_v5.py` and `lint_ppl.py` version 3, which read INPUT's typed fields (`{name,[0]}`). |
| `ppl_check_v5.py` | An error-code tally. E2 is block balance; E3 is more than six names on a LOCAL line; E6 is a LOCAL out of place; E8 is a lowercase exponent or `=` used for `==`; E10 is an INPUT into something that is not a variable (v5, 1 November 2026: a typed field, `{name,[0]}` or `{name,[types],{pos}}`, counts as its name); E11 is a name that is a built-in command, ignoring case, as the calculator does; E12 (new in v4, 17 October 2026) is a `//` comment inside an open bracket, which the Prime rejects as a syntax error (ChiTable beta 3b). Usage: `python3 ppl_check_v5.py whitelist.json,HP_Prime_Builtin_Names.txt FILE.txt`; the whitelist can be an empty list, `[]`. |
| `lint_ppl.py` | Structural lint: block balance, LOCAL sizes, INPUT counts, the CHOOSE pattern, EXPORT discipline. Its "no function named <file>" and EXPORT-discipline lines are expected noise for most programs. Version 2 (19 October 2026) no longer reads the comment lines of `HP_Prime_Builtin_Names.txt` as names, counts `STRING(MAX(a, b), 2, 1)` as three arguments, and reads a list on a LOCAL as one name: over the fleet its reports fall from 649 to 320, none of them new. Version 3 (1 November 2026) checks a form's variables, labels and help lines by the call's own arguments, so a typed field `{name,[0]}` counts once; over the fleet its reports are version 2's. |
| `fleet_names_v2.py` | **The shared-pool check.** All programs on a Prime share one pool of routine names, so two programs that both define `NiceNum` can run each other's. Run `python3 fleet_names_v2.py *.txt` over every program you install. It reports collisions, helpers without their program's tag, files that mix two tags, and helper names that are built-ins. |
| `HP_Prime_Builtin_Names.txt` | The built-in names the checks compare against. |
| `make_tlg1_v2.py` | **A general version from an advanced one** (31 October 2026; v2, 1 November 2026): builds `programs/TTestLabG_beta1a.txt` from `programs/TTestLab_beta1c.txt` (and PowerViz's draft lottery list) by exact replacements, stopping if any text is not found exactly as expected. `python3 tools/make_tlg1_v2.py programs/TTestLab_beta1c.txt programs/PowerViz_v2.5k.txt OUT.txt` gives the filed file byte for byte. A fix goes into the advanced version first, then the general one is rebuilt with the script's next version. |
| `make_starter_pack_v4.py` + `CentralLimit_app_base_v1.hpapp` | **The starter pack** (v4 of the tool, 1 November 2026: checked files). `python3 make_starter_pack_v4.py v6 --kit PATH --checked FOLDER` builds every program in `programs/` into `starter-pack/HP_Prime_Statistics_Starter_Pack_v6.zip` for the Virtual Calculator and writes `starter-pack/README.md`. With `--checked`, each program is the file the Virtual Calculator wrote back after one Check there (the same source plus its compiled block), so students never Check; the tool reads the source out of each checked file and stops unless it equals `programs/<file>.txt`, or if a file carries no block (`docs/changes/StarterPack_v5_NOTES.md`). For CentralLimit only the app's program file comes from FOLDER; its descriptor is built from the `.hpapp` beside the tool. Without `--checked` it builds as v3 did (hp-prime-kit's `hpprime write`), and the instructions keep the Check step. It also writes `Sample data (optional)/M1.hpmat` from `data-loader/examples/rossi.csv` and reads it back value for value. The name checks and the read-back are v3's. Needs Python 3 and hp-prime-kit (not in this repository). |
| `monkey_v1b.py` | **The monkey test** (1 November 2026; v1b the same evening, with `prime_facts_v1.py` applied; the book's vetting point 6, "bulletproof under careless and random use"). `python3 tools/monkey_v1b.py programs/<Name>.txt "CALL()" --runs 1000 --lists [--writes D,C]` runs the program in the harness again and again with random keys, taps, drags, menu picks and cancels, and random values typed into its forms (ordinary numbers, 0, negatives, 1E300, 1E-300, 13 digits, and a list where a field takes any type), some runs with random Statistics lists and a random M1. Each run gets a verdict: CRASH, GUARD, FREEZE, STALL, STATE, HARNESS or OK; a broken run is kept with its seed, and `--replay SEED` repeats it. `--writes` names the Home variables a program is meant to change. Needs `ppl_run_v3e.py` and `prime_facts_v1.py` beside it and hp-prime-kit (`HPKIT`). The first pass: `docs/dev/monkey-fleet-2026-11-01.md`. |
| `prime_facts_v1.py` | **What the Prime does that the harness does not model yet** (1 November 2026, from the Virtual Calculator), added to the harness by a patch: `import prime_facts_v1; prime_facts_v1.apply()` before the first `Harness`. Its facts, each with where and when it was seen: `STRING(x, 2, d)` is "Invalid input" for d ≥ 13; `STRING(x, 3, d)` writes the small capital ᴇ. `monkey_v1b.py` and the verify scripts of SampDist v2.3e and BayesTree beta 8f apply it. A fact the harness cannot take this way, such as `!=` (a factorial and a test on the Prime, "not equal" in the harness), becomes a static check in the verify scripts. The harness's next version is to absorb these. |
| `monkey_chunks_v1.py` | **The monkey's runs in chunks, written as they end** (2 November 2026). `monkey_v1b.py` writes its report only at the end, so a job stopped by a time limit leaves nothing; GaltonBoard's 1,000 runs outlived a two-hour limit. `python3 monkey_chunks_v1.py PROG CALL BASE K0 K1 OUT.jsonl [--lists] [--writes D] [--seconds 120]` runs the very same runs (seed = BASE × 1000003 + k, so `monkey_v1b.py --replay SEED` still repeats any one) and appends a JSON line per run; run again with the same OUT, it resumes. |
| `label_fit_v1.py` | **A number cut short by `TEXTOUT_P`'s width argument** (2 November 2026), which `text_overlap_v1` cannot see (it measures a text as the smaller of its width and that argument). Every text that reads as a number is measured at the narrow glyph widths (5.5 / 6.5 / 7.5 px a character for fonts 1 / 2 / 3, 3 px a decimal point) and reported when even that is wider than its width argument. In a verify script after `text_overlap_v1.install()`: `label_fit_v1.clipped(OV.RECORDS)`; from the command line, on `text_overlap_v1`'s JSON. |
| `monkey_labels_v1.py` | **Every program's labels under random use** (2 November 2026). `python3 monkey_labels_v1.py RUNS [NAME ...] --out DIR` drives each current program in `programs/` with the monkey, `text_overlap_v1`'s recorder on, and reports the firm overlaps, straddles, overruns and cut numbers (`label_fit_v1`). The first run, 100 a program: `docs/dev/label-check-2026-11-02.md`. |
| `commas_v1.py` + `commas_config_r5.py` | **Commas in big numbers** (2 November 2026, round 5; Roger: "always put comma delimiters in big numbers"). `python3 commas_v1.py NAME OLD.txt NEW.txt` makes a program's next version by fixed rules: the comma routine (`<prefix>Cm`) before the first routine; every `STRING` and number formatter call wrapped where it is made, except in text the CAS or `EXPR` reads and in the routines that build such text; at the screen, only text that may still hold an ungrouped number (from the CAS, from `EXPR`, from those routines); numbers in the program's own wording grouped in the literal, never a year. `commas_config_r5.py` says, program by program, which routines are formatters, which are left alone, and the exact edits of the round (layout where a number with its commas no longer fitted). |
| `comma_check_v1.py` + `comma_helper_reference_v1.txt` | **The check of round 5**, called by each program's round-5 verify script: G, static (the routine word for word as in the reference; with every call of it taken out, the code is the old version's but for the routines the change note names; nothing the CAS reads goes through it); R, the monkey on both versions, 30 seeds, the same path once the commas are out; C, the same texts handed to the CAS and `EXPR`, call for call; M, every number of four or more digits drawn is grouped; Y, no year or name with digits in it ("x1000") is; D, no new overlap or cut number. |
| `ppl_run_v3e.py` + `ppl_run_v3e_README.md` | **A run harness**: it runs a PPL program on the PC like a student at the keys. A script supplies keys, taps, drags, CHOOSE picks and INPUT answers. The statistics built-ins are backed by SciPy, and `CAS("...")` is answered by desktop Giac, the engine inside the Prime's CAS (`apt-get install xcas` gives `icas`). It records every screen drawn. It needs hp-prime-kit's interpreter, SciPy, and, for CAS calls, Giac. Since v3b it follows what the Prime's firmware did on the emulator: `CAS(variable)` comes back unevaluated, and CAS answers are printed the Prime's way. Since v3c, soft-key taps under `WAIT(-1)` arrive as clicks, and the chi-square and F built-ins refuse a fractional df. Since v3d (the second emulator round), `INSTRING` on an empty string is an error, and `STRING(x, 2, d)` turns scientific below 10⁻ᵈ. v3e adds the Prime's Unicode minus in that exponent, with `home_minus=True`. Its README covers v3d too. Agreement in the harness is not agreement on the device, but it has caught real bugs before a paste. |

The checks are only as good as their rules, and those rules come from the device. When the calculator disagrees with a tool, the calculator wins, and the rule gets fixed and written into the newest `docs/lessons-learned_v7*.md`.
