# Tools

Every program in this repository passes these checks before it is pasted onto a calculator. They are plain Python 3, and only `ppl_run_v3e.py` needs more (see below).

| File | What it does |
| --- | --- |
| `ppl_gate_v1c.py` | **The gate.** `python3 ppl_gate_v1c.py NEW.txt [ORIGINAL.txt]` runs the four checks below and the fleet name check, and prints PASS or the lines to look at. It finds the other tools and `HP_Prime_Builtin_Names.txt` in its own folder (or one folder up), so keep them together. It uses hp-prime-kit's linter and interpreter if it can find them (JordiRigau/hp-prime-kit, as `Community_Library/github/JordiRigau__hp-prime-kit.zip` beside it or one folder up); without them those two steps are skipped. v1c (19 October 2026) runs the kit's linter on a copy with the `#PYTHON … #END` blocks blanked, so a program carrying MicroPython no longer shows a false "unbalanced blocks" error, and uses `lint_ppl.py` version 2. v1b (17 October 2026) made `ppl_check_v4.py`'s E12 a hard error. |
| `ppl_check_v4.py` | An error-code tally. E2 is block balance; E3 is more than six names on a LOCAL line; E6 is a LOCAL out of place; E8 is a lowercase exponent or `=` used for `==`; E10 is an INPUT into something that is not a variable; E11 is a name that is a built-in command, ignoring case, as the calculator does; E12 (new in v4, 17 October 2026) is a `//` comment inside an open bracket, which the Prime rejects as a syntax error (ChiTable beta 3b). Usage: `python3 ppl_check_v4.py whitelist.json,HP_Prime_Builtin_Names.txt FILE.txt`; the whitelist can be an empty list, `[]`. |
| `lint_ppl.py` | Structural lint: block balance, LOCAL sizes, INPUT counts, the CHOOSE pattern, EXPORT discipline. Its "no function named <file>" and EXPORT-discipline lines are expected noise for most programs. Version 2 (19 October 2026) no longer reads the comment lines of `HP_Prime_Builtin_Names.txt` as names, counts `STRING(MAX(a, b), 2, 1)` as three arguments, and reads a list on a LOCAL as one name: over the fleet its reports fall from 649 to 320, none of them new. |
| `fleet_names_v2.py` | **The shared-pool check.** All programs on a Prime share one pool of routine names, so two programs that both define `NiceNum` can run each other's. Run `python3 fleet_names_v2.py *.txt` over every program you install. It reports collisions, helpers without their program's tag, files that mix two tags, and helper names that are built-ins. |
| `HP_Prime_Builtin_Names.txt` | The built-in names the checks compare against. |
| `ppl_run_v3e.py` + `ppl_run_v3e_README.md` | **A run harness**: it runs a PPL program on the PC like a student at the keys. A script supplies keys, taps, drags, CHOOSE picks and INPUT answers. The statistics built-ins are backed by SciPy, and `CAS("...")` is answered by desktop Giac, the engine inside the Prime's CAS (`apt-get install xcas` gives `icas`). It records every screen drawn. It needs hp-prime-kit's interpreter, SciPy, and, for CAS calls, Giac. Since v3b it follows what the Prime's firmware did on the emulator: `CAS(variable)` comes back unevaluated, and CAS answers are printed the Prime's way. Since v3c, soft-key taps under `WAIT(-1)` arrive as clicks, and the chi-square and F built-ins refuse a fractional df. Since v3d (the second emulator round), `INSTRING` on an empty string is an error, and `STRING(x, 2, d)` turns scientific below 10⁻ᵈ. v3e adds the Prime's Unicode minus in that exponent, with `home_minus=True`. Its README covers v3d too. Agreement in the harness is not agreement on the device, but it has caught real bugs before a paste. |

The checks are only as good as their rules, and those rules come from the device. When the calculator disagrees with a tool, the calculator wins, and the rule gets fixed and written into `docs/lessons-learned_v7j.md`.
